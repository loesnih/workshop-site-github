# Игровая лаборатория

Единый статический проект мастер-класса. Новых локаций здесь нет: исходные сцены скопированы из рабочей папки и подключены к общему меню.

## GitHub Pages

1. Создайте публичный репозиторий.
2. Загрузите **содержимое этой папки** в корень репозитория, сохранив вложенные папки. Не загружайте только ZIP.
3. В Settings → Pages выберите Deploy from a branch, ветку main, папку / (root).
4. Дождитесь публикации. Адрес будет вида `https://USERNAME.github.io/REPOSITORY/`.
5. QR-код направьте на этот адрес. Свой домен не требуется.

Все внутренние пути относительные, сайт подходит для размещения в подпапке репозитория.

## Структура

- `index.html` — главное меню.
- `viewer.html?demo=ID` — пример с общей панелью возврата и переключения.
- `generator/index.html` — обновлённый конструктор промптов.
- `demos/` — изометрия, варианты станций, терминал, карта и архив AR.
- `assets/` — общие стили, навигация и используемые версии Three.js.
- `source-manifest.json` — соответствие копий исходным файлам и список адаптаций.

Каждая страница демонстрации также имеет кнопку возврата при прямом открытии. Панель оболочки не накладывается на интерфейс сцен. При переключении пример перезапускается. Состояние терминала и карты сохраняется их исходными механизмами в браузере, общей синхронизации между ними нет.

## Конструктор

Убраны выбор визуального стиля и настройка сохранения игрового прогресса после закрытия. Детализация сохранена. Каждый промпт запрашивает готовый `index.html` для скачивания **и** полный код. Если используемый чат не умеет прикреплять файлы, промпт просит сообщить об этом и вывести код полностью.

Сохранение настроек самого конструктора в браузере оставлено. Это не сохранение игрового прогресса.

## Зависимости и запуск

Исходные версии Three.js сохранены локально, в сценах заменены только пути загрузки. Лицензия находится в `assets/vendor/`. AR.js и A-Frame включены в архивный пример вместе с лицензиями.

Для проверки используйте GitHub Pages или обычный локальный HTTP-сервер. Сцены с ES-модулями не следует проверять через `file://`. AR требует камеры и совместимости устройства; AR через WebXR не гарантирован даже при наличии HTTPS.
